# 저장소에 CI4 프로젝트 넣고 회차 태그 찍기

강좌 저장소(`nambak/ci4board`)를 실제로 굴러가게 만드는 절차입니다. 한 번만 하면 되는 초기 작업과, 매 회차 반복할 작업으로 나눠 적었습니다.

---

## 0. 지금 상태와 목표

현재 저장소에는 이런 것들이 들어 있습니다.

```
ci4board/
├── .gitignore
├── README.md
├── CURRICULUM.md
├── docs/
│   ├── ep01.md
│   └── ep02.md
├── assets/cover/
└── app/
    ├── Commands/VerifyCasts.php
    ├── Database/Migrations/   ← 12개 (ep04 ~ ep33 시점의 것이 전부)
    └── Models/PostModel.php
```

빠진 것은 **CodeIgniter 4 프로젝트 본체**입니다. `public/`, `system/`(vendor), `composer.json`, `spark`, `env`, `writable/` 등이 없어서 지금 상태로는 `php spark`가 돌지 않습니다.

목표는 두 가지입니다.

1. CI4 appstarter를 이 저장소 안에 얹어서 **실행 가능한 프로젝트**로 만들기
2. 회차 태그가 **독자에게 정직하게 동작**하도록 파일 배치 정리하기

---

## 1. 먼저 정리할 것 — 미래 회차 파일을 빼둔다

이게 중요합니다. 먼저 짚고 갑니다.

지금 `app/Database/Migrations/` 에는 마이그레이션 12개가 전부 들어 있습니다. 설계 검증을 하느라 미리 만든 것입니다. 그런데 이 상태로 `ep02` 태그를 찍으면 이런 일이 생깁니다.

```bash
git checkout ep02     # 독자가 2편 시점 코드를 받았는데
ls app/Database/Migrations/
# ep33에서나 나올 reports 테이블 마이그레이션이 이미 있다
```

2편은 "빈 프로젝트를 세팅한다"는 편인데 독자 손에는 30편 뒤의 코드가 들어 있는 셈입니다. 원고와 코드가 어긋나면 태그를 붙이는 의미가 사라집니다.

그래서 검증용 마이그레이션은 **참고 자료 자리로 옮기고**, `app/Database/Migrations/` 는 회차가 진행되면서 하나씩 채웁니다.

```bash
cd ~/Project/ci4board

mkdir -p _design/migrations
git mv app/Database/Migrations/*.php _design/migrations/
git mv app/Models/PostModel.php      _design/PostModel.php
git mv app/Commands/VerifyCasts.php  _design/VerifyCasts.php

git commit -m "chore: 검증용 코드를 _design 으로 분리

회차 태그가 실제 진행 상황과 일치하도록,
설계 검증 단계에서 만든 파일을 참고 자료 자리로 옮긴다.
app/ 아래에는 회차가 진행되면서 하나씩 복사해 넣는다."
```

`_design/` 은 독자가 봐도 되는 자료입니다. README에 "이 폴더는 전체 설계 검증본이며, 회차별 코드는 태그를 보세요"라고 한 줄 적어두면 됩니다.

> 회차가 진행될 때는 `cp _design/migrations/...000001_CreateUsersTable.php app/Database/Migrations/` 처럼 그 편에 필요한 것만 복사해 넣습니다. 이미 검증된 파일이라 다시 만들 필요가 없습니다.

## 2. CI4 프로젝트 얹기

### 왜 그냥 `composer create-project` 를 못 쓰는가

`composer create-project codeigniter4/appstarter .` 는 **디렉토리가 비어 있어야** 동작합니다. 우리 폴더에는 이미 `README.md`, `docs/` 등이 있어서 거부당합니다.

그래서 **임시 폴더에 만들고 내용물만 옮기는** 방식으로 갑니다.

### 절차

```bash
cd ~/Project

# 1) 임시 폴더에 appstarter 를 받는다
#    --remove-vcs 를 반드시 붙인다 (아래 설명)
composer create-project codeigniter4/appstarter _ci4tmp --remove-vcs

# 2) 우리 저장소로 내용물을 옮긴다
#    -R 은 디렉토리를 병합한다. app/ 아래 우리 파일은 그대로 남는다
cd _ci4tmp
cp -R app builds env phpunit.dist.xml preload.php public spark tests writable composer.json composer.lock ~/Project/ci4board/

cd ~/Project
rm -rf _ci4tmp
```

### `--remove-vcs` 를 빠뜨리면

appstarter는 GitHub 저장소에서 내려받는 것이라 `.git` 폴더가 딸려옵니다. 이걸 안 지우면 프로젝트 안에 **CodeIgniter 공식 저장소를 가리키는 git 저장소**가 하나 더 생깁니다. 나중에 `git remote -v` 를 찍었을 때 이런 게 나오면 그 상황입니다.

```
origin  https://github.com/codeigniter4/appstarter.git (fetch)
```

이 상태로 `git push` 를 하면 엉뚱한 곳으로 갑니다. 이미 그렇게 됐다면 임시 폴더의 `.git` 을 지우고 다시 복사하면 됩니다.

### 덮어쓰지 말아야 할 파일

`cp -R` 로 옮길 때 아래 두 개는 **목록에서 뺐습니다.** appstarter에도 같은 이름이 있지만 우리가 만든 것을 써야 합니다.

| 파일 | 이유 |
|---|---|
| `.gitignore` | 우리 것이 `writable/` 하위와 macOS 파일까지 더 촘촘하게 잡는다 |
| `README.md` | 강좌 소개로 이미 채워 뒀다 |

혹시 실수로 덮어썼다면 되돌릴 수 있습니다.

```bash
git checkout -- .gitignore README.md
```

### `env` 는 올리고 `.env` 는 안 올린다

헷갈리기 쉬운 부분입니다.

- **`env`** (점 없음) — appstarter가 주는 예시 파일. **저장소에 올립니다.** 독자가 복사해서 쓸 원본입니다.
- **`.env`** (점 있음) — 내 DB 비밀번호가 든 실제 설정. **절대 올리지 않습니다.** `.gitignore` 에 이미 들어 있습니다.

```bash
cp env .env
# .env 를 열어 DB 접속 정보를 채운다
```

## 3. 동작 확인

```bash
cd ~/Project/ci4board

php spark --version        # CodeIgniter v4.7.x
php spark db:table --show  # 접속 정보 + "Database has no tables!"
php spark serve            # http://localhost:8080 에서 환영 화면
```

`writable/` 에 쓰기 권한이 없으면 에러가 납니다.

```bash
chmod -R 775 writable
```

그리고 `.env` 가 정말로 추적되지 않는지 확인합니다. **이건 꼭 보세요.**

```bash
git status --short | grep -F '.env'
# 아무것도 안 나와야 정상
```

## 4. 첫 커밋과 `ep02` 태그

```bash
git add -A
git status --short      # .env, vendor/ 가 없는지 눈으로 확인

git commit -m "chore: CI4 4.7 appstarter 도입과 DB 연결

- appstarter 기본 구조 추가
- .env 예시(env) 포함, 실제 .env 는 추적 제외
- database.default.DBCollat 을 utf8mb4_unicode_ci 로 명시"
```

태그를 붙입니다.

```bash
git tag -a ep02 -m "ep02: 프로젝트 세팅과 이 강좌의 규칙"
```

`-a` 는 주석이 달린(annotated) 태그를 만듭니다. 만든 사람과 날짜, 메시지가 함께 저장됩니다. `git tag ep02` 처럼 `-a` 없이 만드는 가벼운(lightweight) 태그는 커밋을 가리키는 이름표일 뿐이라 정보가 남지 않습니다. 강좌처럼 오래 두고 참조할 것에는 `-a` 를 쓰는 편이 좋습니다.

원격에 올립니다.

```bash
git remote add origin https://github.com/nambak/ci4board.git   # 최초 1회
git push -u origin main
git push origin ep02
```

`git push origin ep02` 처럼 태그를 하나씩 지정해 올리는 것을 권합니다. `--tags` 는 로컬의 모든 태그를 한꺼번에 밀어 올리는데, 실험하다 만든 태그까지 딸려 올라갈 수 있습니다.

## 5. 매 회차 반복하는 절차

3편부터는 이 순서를 반복합니다. 기획서에 적어둔 **"코드가 먼저, 원고가 나중"** 원칙 그대로입니다.

```bash
# 1) 그 편의 코드를 작업한다
cp _design/migrations/2026-08-11-000001_CreateUsersTable.php app/Database/Migrations/
# ... 편집, 실행, 확인

php spark migrate
php spark serve      # 브라우저에서 눈으로 확인

# 2) 원고를 쓴다
vi docs/ep04.md

# 3) 대표 이미지를 뽑는다
cd assets/cover && python make_cover.py --style a --ep 4 --out cover_ep04.png && cd -

# 4) 한 번에 커밋하고 태그
git add -A
git commit -m "feat: 마이그레이션 - users, boards"
git tag -a ep04 -m "ep04: 마이그레이션 ①: users, boards"
git push origin main
git push origin ep04

# 5) 블로그 발행
```

**회차 중간에 커밋을 쪼개지 않는 이유**는 태그가 가리키는 지점이 "그 편을 다 읽고 난 뒤의 상태"여야 하기 때문입니다. 독자가 `git checkout ep04` 했을 때 글의 마지막 문단과 코드가 정확히 맞아야 합니다.

작업 중에 여러 번 커밋하고 싶다면, 회차용 브랜치에서 자유롭게 커밋한 뒤 `main` 에 스쿼시 병합하는 방법이 있습니다.

```bash
git switch -c work/ep04
# ... 마음대로 커밋
git switch main
git merge --squash work/ep04
git commit -m "feat: 마이그레이션 - users, boards"
git branch -D work/ep04
```

## 6. 태그를 잘못 찍었을 때

### 아직 push 하지 않았다면

```bash
git tag -d ep04
git tag -a ep04 -m "ep04: ..."     # 다시 찍기
```

### 이미 push 했다면

```bash
git push origin --delete ep04      # 원격에서 지우고
git tag -d ep04                    # 로컬에서 지우고
git tag -a ep04 -m "ep04: ..."     # 다시 찍고
git push origin ep04               # 다시 올린다
```

이건 **글을 발행하기 전까지만** 마음 편히 할 수 있습니다. 발행한 뒤에 태그가 가리키는 커밋이 바뀌면, 이미 그 태그로 코드를 받아간 독자와 다른 코드를 보게 됩니다. 그래서 기획서에서 스키마를 미리 확정한 것입니다.

### 발행 후에 버그를 발견했다면

태그를 옮기지 말고 **뒤에 붙이는** 쪽을 권합니다.

```bash
git tag -a ep04.1 -m "ep04.1: users 테이블 인덱스 수정"
```

그리고 원래 글에 "이 편 발행 후 `ep04.1` 에서 인덱스를 하나 고쳤습니다"라고 한 줄 덧붙입니다. 이전 강좌에서 28편을 "버그 수정과 코드 정리"로 따로 뺀 것도 같은 맥락입니다.

## 7. 독자가 받아 가는 방법 (README에 적을 내용)

```bash
git clone https://github.com/nambak/ci4board.git
cd ci4board

git checkout ep12          # 12편 시점

composer install
cp env .env                # DB 접속 정보 입력
php spark migrate
php spark serve
```

`git checkout <태그>` 는 detached HEAD 상태가 됩니다. 독자가 거기서 코드를 고쳐 보고 싶다면 브랜치를 하나 파면 됩니다. README에 한 줄 적어두면 친절합니다.

```bash
git switch -c my-ep12 ep12
```
